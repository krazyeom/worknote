# 2026-10-31 작업 노트: aWord 영한 대조 학습 엔진 및 블로그 다국어 시스템 구축

* **작업 대상**: aWord Web Markdown Editor & Blog Platform
* **핵심 주제**: 1:1 영한 대조 학습, 24kHz Studio AI 음성 파이프라인, 실시간 배속 및 3단계 루프, 블로그 EN/KO 동기화
* **문서 성격**: 엔지니어링 실행 기록 및 기술 결정 사항 정리

---

## 1. 당일 작업 개요

작성한 한국어 글을 문장 단위로 분할하여 영어로 직독직해 번역하고, 원어민 AI 음성으로 실시간 섀도잉 학습을 진행할 수 있는 **동시 하이라이트 튜터 엔진**을 개발했습니다.  
이어서 블로그 페이지에 다국어(EN/KO) 전환 체계를 구축하고, 플랫폼 전반의 사용자 경험과 오디오 재생 안정성을 개선했습니다.

---

## 2. 주요 구현 내용

### A. 1:1 문장 정합 번역 및 백그라운드 캐시 파이프라인
* **마크다운 본문 정제 (`markdown-plain.ts`)**:
  * 음성 학습에 부적합한 코드 블록(```), 인라인 코드(`), 쉘 명령어(`npm`, `git`, `curl` 등), URL, 프론트매터를 정규식으로 완벽히 소거했습니다.
  * 순수 서술형 문장만 추출하여 LLM에 전달하도록 설계했습니다.
* **7문장 청크 분할 및 안전 파싱 (`study-pipeline.ts`)**:
  * LLM(Gemini Flash) 호출 시 컨텍스트 초과와 응답 잘림을 방지하고자 전체 본문을 7문장 단위로 묶어 번역을 요청했습니다.
  * 불완전한 JSON 응답에 대비하여 자가 복구 파서(`extractJsonPairs`)를 구현했습니다.
* **SHA-256 디스크 영구 캐시 (`study-cache.ts`)**:
  * 정제된 본문의 SHA-256 해시를 키로 삼아 `data/study_cache/*.study.json` 파일로 저장했습니다.
  * 글 발행 시 백그라운드 워커가 즉각 번역을 선행 수행하며, 본문이 바뀌지 않는 한 추가 API 호출 없이 0ms로 응답합니다.

---

### B. 24kHz Studio AI 오디오 엔진 및 0ms 프리페치
* **16-bit 24kHz Linear PCM $\rightarrow$ WAV 변환 (`gemini-audio.ts`)**:
  * Google Gemini Flash 모델의 오디오 모달리티를 연동하여 스튜디오 품질 원어민 성우(`Kore`, `Puck`, `Charon`, `Fenrir`) 음성을 생성했습니다.
  * 수신된 24kHz Linear PCM 바이너리를 웹 표준 RIFF WAV 컨테이너로 직접 패킹했습니다.
* **디스크 캐시 및 무지연 프리페치**:
  * 생성된 WAV 음원은 해시 기반으로 디스크에 영구 보관되며, HTTP 응답 시 1년 불변 캐시 헤더(`Cache-Control: immutable`)를 반환합니다.
  * 현재 문장 재생 시작 직후 브라우저 `fetch`로 다음 2개 문장을 선행 로드하여 문장 전환 시 네트워크 지연을 없앴습니다.

---

### C. 재생 제어 및 UI 인터랙션 최적화
* **3단계 루프 모드 (Loop Mode)**:
  * 반복 버튼 클릭 시 `반복 끄기(none)` $\rightarrow$ `문장 반복(sentence, S)` $\rightarrow$ `전체 문장 반복(all, A)` $\rightarrow$ `반복 끄기(none)` 순으로 상태가 순환합니다.
  * 버튼 아이콘 위에 주황색 `S`와 파란색 `A` 뱃지를 겹쳐 표시하여 현재 동작 모드를 직관적으로 식별할 수 있도록 다듬었습니다.
* **실시간 배속(0.5x~2.0x) 연동 및 리셋 방어**:
  * `audio.src` 주입 시 브라우저가 `playbackRate`를 기본값(1.0)으로 초기화하는 현상을 방어하고자 `defaultPlaybackRate`와 `playbackRate`를 순차 재지정했습니다.
  * 재생 중 배속을 변경해도 문장을 처음부터 다시 틀지 않고 현재 재생 시점에 즉시 반영되도록 구현했습니다.
* **Zero-Layout-Shift 인라인 하이라이터**:
  * 단어 활성화 시 폰트 굵기를 바꾸지 않고 텍스트/배경 색상만 인라인 `<mark>`로 전환하여 문장 끝 줄바꿈이 떨리는 현상을 제거했습니다.
  * 발화 진행률의 중심점(`(start + end) / 2`)에 일치하는 단어 토큰 1개만 켜지도록 스냅 알고리즘을 적용했습니다.
  * 영문 전용 독해 모드(`english_only`)에도 `RealtimeEnglishSentence`를 동일하게 연결하여 단어별 실시간 하이라이트가 누락 없이 동작하도록 조치했습니다.
* **원문 서식 렌더링 지원**:
  * 좌측 패널에 날것의 `textarea` 대신 `MarkdownView`를 기본 노출하여 읽기 경험을 향상시켰습니다.
  * `[원문 편집]` / `[서식 보기]` 버튼으로 모드를 즉시 전환할 수 있습니다.

### D. 블로그 다국어(I18n) 시스템 구축
* **언어 스위처 탑재 (`LanguageToggle.tsx`, `useLanguage.ts`)**:
  * 기존에 에디터에만 존재하던 `EN / KO` 토글 버튼을 블로그 목록과 글 상세 페이지 상단 헤더에도 동일하게 배치했습니다.
  * `localStorage`와 브라우저 커스텀 이벤트를 연동하여 에디터와 블로그 어느 곳에서 언어를 바꾸더라도 화면 전반에 실시간 반영됩니다.
* **블로그 피드 메타바 가독성 개선**:
  * 게시글 제목 위에 표시되던 TTS 캐시 배지를 카드 하단 메타데이터 바(날짜, 읽기 시간 우측)로 이동하여 글 제목 본연의 가독성을 확보했습니다.

| **TTS 음성 엔진** | **Google Studio 24kHz AI 성우 단일화** | iOS Web Speech API: Safari 제약으로 신경망 Siri 음성이 지원되지 않고 8kHz 구형 기계음(`Samantha Compact`)만 노출되어 제외 |

| **오디오 세션 관리** | **단일 HTMLAudioElement 재사용** | 문장마다 `new Audio()` 생성: iOS Safari의 사용자 인터랙션 보호 정책으로 인해 비동기 자동 재생이 차단됨 |

| **반복 재생 방식** | **3단계 순환 토글 (문장 S / 전체 A / 끔)** | 단순 토글: 전체 문장 무한 순환 청취 요구를 수용하지 못함 |

# 2026-10-31 작업 노트: subtitle-to-speech 영화 대본 TTS 섀도잉 및 대용량 배치 슬라이서 구축

* **작업 대상**: `subtitle-to-speech` (영화 각본 및 자막 기반 TTS 섀도잉 플레이어)
* **핵심 주제**: 영화 대본 아카이브 뷰, 노팅힐 12개 메이저 챕터(936개 대사), 오디오 팝/클릭 노이즈 원천 박멸, 남녀 배역 음성 자동 분기, 대용량 배치 묶음 호출 및 오디오 슬라이서(Audio Slicer)
* **문서 성격**: 엔지니어링 실행 기록 및 아키텍처 결정 사항(ADR)

---

## 1. 당일 작업 개요

영화 자막과 시나리오를 원어민 AI 음성(Google Gemini Flash TTS)으로 청취하며 영어 섀도잉 학습을 진행할 수 있는 웹 플랫폼 **subtitle-to-speech**를 신규 구축했습니다.  
블로그 작성/편집 중심의 기존 구조에서 에디터를 걷어내고, 영화 대본 감상 및 자막 파일 임포트/재생 중심의 미니멀 시나리오 아카이브 형태로 재설계했습니다. 개발 중 대두된 대사 끝부분 팝 노이즈(지직거림)를 신호 처리 기법과 브라우저 오디오 객체 재사용으로 완전히 해결했으며, API 호출 한도(Quota) 문제를 극복하기 위해 대량 텍스트 묶음 호출 및 오디오 자동 분할(Audio Slicing) 기반 사전 캐싱 시스템을 완성했습니다.

## 2. 주요 구현 내용

### A. 시나리오 데이터셋 구축: 노팅힐 12개 메이저 챕터 (총 936개 대사)
* **IMSDb 원본 각본 전편 파싱**:
  * 리처드 커티스(Richard Curtis)의 노팅힐 원작 시나리오(약 11만 8천 자)에서 장소 지문(`EXT./INT.`), 등장인물 이름(`WILLIAM`, `ANNA` 등), 실제 발화 대사를 추출했습니다.
* **서사 기반 12개 챕터 통합**:
  * 지문 변경 시마다 자잘하게 잘려 대사가 1~2개뿐이던 100개 미니 씬 문제를 해결하고자, 영화의 기승전결에 맞춰 **12개의 큼직한 메이저 챕터(챕터당 정확히 78개 대사)**로 통합 재구성했습니다.
  * 오프닝 포토벨로 로드 거리부터 마지막 리츠 호텔 기자회견 씬까지 영화 전편 936개 대사를 끊김 없이 호흡하며 감상할 수 있습니다.

### B. 오디오 팝/클릭 노이즈(지직 소리) 원천 박멸
* **PCM 버퍼 끝 절단 노이즈 해결 (`lib/gemini-audio.ts`)**:
  * Gemini API가 반환한 16-bit 24kHz Linear PCM의 마지막 샘플이 높은 진폭(약 24,000)에서 감쇄 없이 잘려 스피커 진동판이 원점으로 튀면서 팝 노이즈가 발생하던 결함을 발견했습니다.
  * `pcmToWav` 변환 시 **80ms 소프트 페이드아웃(factor^1.5 쿼드라틱 감쇄)**과 **60ms 완전 무음(Zero-padding)**을 추가하여 오디오 파형이 0으로 완벽히 수렴하도록 조치했습니다.
* **브라우저 오디오 버퍼 파쇄음 차단 (`components/SubtitlePlayer.tsx`)**:
  * 대사 전환 시 `audio.src = ''`를 실행하면 브라우저 하드웨어 버퍼가 강제 플러시되면서 스피커에서 찌익 소리가 발생하던 문제를 발견했습니다.
  * `HTMLAudioElement` 객체를 단일 인스턴스로 영구 재사용하도록 변경하고, 대사 종료 직전 80ms 동안 `audio.volume`을 부드럽게 감쇄(Soft Mute)하도록 교정했습니다.

### C. 남녀 배역 음성 자동 분기 및 성별 맞춤 캐싱 (`lib/gender-voice.ts`)
* **인물 성별 자동 인식**:
  * 각본 속 화자명을 분석하여 여성 배역(`Anna`, `Honey`, `Bella`, `Karen` 등)은 차분한 여성 보이스 **`Kore`**, 남성 배역(`William`, `Spike`, `Bernie`, `Max` 등)은 매력적인 영국/미국풍 남성 보이스 **`Puck`**으로 자동 배정합니다.
* **플레이어 기본 적용**:
  * 플레이어 하단 보이스 선택 메뉴의 기본값을 `⚡ 남녀 배역 자동 (Auto)`으로 설정하여, 별도의 수동 조작 없이도 안나 스콧과 윌리엄의 목소리가 실제 영화처럼 남녀 목소리로 교차 재생됩니다.

### D. 대용량 묶음 호출 및 오디오 자동 슬라이서 (`lib/audio-slicer.ts`)
* **API 호출 한도(429 Quota) 극복 원리**:
  1. 챕터 내에서 남성 대사와 여성 대사를 각각 **최대 15개 단위(약 1,000~2,000자)의 긴 텍스트로 합쳐서 단 1번의 API로 호출**합니다.
  2. 반환된 대용량 Linear PCM 오디오를 자체 구현한 **스마트 오디오 슬라이서(`slicePcmToCues`)**가 대사 사이의 무음(Silence, RMS 에너지 탐지)과 글자 수 비율을 감지하여 각 대사 단위로 정밀 분할합니다.
  3. 쪼개진 15개의 대사 오디오는 각각 부드러운 페이드인/아웃과 무음 패딩을 거쳐 개별 캐시 파일(`audio_hash.wav`)로 디스크에 즉시 저장됩니다.
* **효율 결과**:
  * 챕터당 78개 대사를 처리하는 데 단 **4~6회의 API 호출**만 소모됩니다.
  * 영화 1편 전체(936개 대사)를 캐시하는 데 필요한 총 호출 수가 **1,000회 이상에서 단 84회로 92% 이상 격감**했습니다.

### E. 관리자(ADMIN) 권한 기반 자막 수정 제어 (`lib/auth.ts`)
* **환경 변수 바인딩**: `.env`에 정의된 `ADMIN_ID` 및 `ADMIN_PASSWORD`를 기준으로 관리자 자격을 검증합니다.
* **보안 세션 토큰**:
  * 로그인 성공 시 HMAC-SHA256 기반 암호화 세션 쿠키(`subtitle_session`, 7일 유효, HttpOnly, SameSite=Lax)를 발급합니다.
  * 타이밍 공격(Timing Attack) 방어를 위해 상수 시간 해시 비교(`crypto.timingSafeEqual`)를 적용했습니다.
* **자막 수정 및 등록 게이트키퍼**:
  * 비로그인 일반 사용자가 자막 수정 버튼이나 스크립트 임포트를 클릭할 경우, 관리자 인증 모달이 먼저 호출됩니다.
  * 백엔드 `POST /api/movies` 엔드포인트에서도 쿠키 세션을 검증하여 비인가자의 자막 임의 수정을 원천 차단했습니다.

### G. 브라우저 로컬 스토리지 기반 개인별 재생 기록 격리
* **클라이언트 격리 저장**: 이어듣기 진행 상황은 서버 데이터베이스가 아닌 각 접속자의 웹 브라우저 로컬 저장소(`localStorage.getItem('s2s_progress_${movieId}')`)에만 보관됩니다. 이에 따라 동시 접속자가 많아도 다른 사용자의 재생 기록과 절대 섞이지 않고 독립적으로 유지됩니다.
* **불필요한 타 영화 버튼 제거**: 상단 노팅힐 히어로 배너 안에 오배치되었던 러브 액츄얼리 버튼을 삭제하고, 아카이브 목록 카드로 정상 분리했습니다.
* **진행 기록 리셋 동작 정밀화**: 실질적인 진행(씬 2 이상 또는 대사 2번 이상)이 없는 초기 상태에서는 불필요하게 '이어듣기'가 노출되지 않도록 필터링하고, `RESET` 클릭 시 로컬 스토리지 키를 즉시 삭제하도록 수정했습니다.

### J. 대사별 순차 큐 연속 재생 및 백그라운드 프리페치 엔진 (`components/SubtitlePlayer.tsx`)
* **단일 통 오디오 추정 방식 폐기 및 싱크 어긋남 원천 차단**:
  * 기존 '씬 전체' 모드에서 78개 대사를 통째로 하나의 오디오로 묶고 글자 수 비율로 시작 지점을 추정하던 방식(`playSceneFlow`)을 전면 폐기했습니다. 글자 수와 실제 발화 시간의 불일치로 인해 3~4번째 대사부터 싱크가 수 초 이상 누적 드리프트되던 문제를 해결했습니다.
  * 모든 재생 흐름을 **대사 단위 개별 완결형 오디오(`playCue`)의 자동 전진(Auto-Advance) 파이프라인**으로 일원화했습니다. 각 대사마다 자신의 시작 지점(`0.0s`)과 정확한 재생 시간을 가지므로, 씬의 처음부터 끝까지 1밀리초의 오차도 없이 목소리와 텍스트가 정확히 일치합니다.
* **0ms 무지연 전환을 위한 2단계 사전 프리페치**:
  * 현재 대사가 재생되는 즉시 백그라운드에서 다음 2개 대사 오디오(`index + 1`, `index + 2`)를 미리 fetch하여 브라우저 HTTP 캐시에 적재합니다. 이에 따라 대사 종료 시 네트워크 대기 시간 없이 즉각 다음 대사로 매끄럽게 연결됩니다.

### L. 328초 선두/후미 무음 제거 및 60fps rAF 하이라이터 추적 (`lib/gemini-audio.ts`, `components/SubtitlePlayer.tsx`)
* **음성 지연(밀림)의 실측 원인 적발**:
  * 디스크 오디오 캐시 전수 분석 결과, Gemini TTS가 생성한 Linear PCM 원본에 **최대 1,078ms(1초 이상)의 선두 무음(Leading Silence)**과 수백 ms의 후미 무음이 잔존하고 있음을 발견했습니다.
  * 첫 1초 동안 스피커에서는 소리가 나지 않는데 플레이어 시간(`currentTime`)은 계속 흘러가므로 하이라이트가 음성보다 앞서 나가고, 대사 종료 후에도 1초 동안 침묵이 이어져 전반적으로 느리고 굼뜨게 밀리는 느낌을 주었습니다.
* **스마트 무음 트리밍(Smart Silence Trimming) 및 전수 재인코딩**:
  * `pcmToWav`에 10ms 단위 진폭 탐지 엔진을 탑재하여 30ms 프리롤과 50ms 포스트롤을 제외한 불필요한 선두/후미 침묵을 자동으로 잘라내도록 개편했습니다.
  * 기존 캐시된 541개 오디오 파일 전수에서 **총 328.5초(약 5.5분)의 공백 무음을 일괄 제거**하여 재생 즉시(30ms 이내) 음성이 칼같이 시작되도록 최적화했습니다.
* **60fps `requestAnimationFrame` 초정밀 싱크 추적**:
  * 브라우저의 `ontimeupdate` 이벤트가 초당 3~4회(250ms 주기)로 드문드문 발생하는 한계를 극복하기 위해 `requestAnimationFrame` 기반 60Hz 렌더 루프를 결합했습니다. 하이라이트가 16ms 주기로 부드럽게 갱신되어 음성과 텍스트가 완벽한 한 몸처럼 일치합니다.

## 4. 아키텍처 결정 사항 (ADR 요약)

* **ADR-1: 단일 Audio 객체 재사용 및 소프트 볼륨 감쇄 (Zero-Click Playback)**
  * 결정: `new Audio()`의 빈번한 생성/파기와 `audio.src = ''` 호출을 전면 금지하고, 컴포넌트 라이프사이클 내 단일 오디오 인스턴스를 유지하며 대사 전환 시 볼륨 페이더를 경유합니다.
  * 이유: OS 오디오 드라이버와 브라우저 DAC 간의 버퍼 언더런으로 인한 하드웨어 팝 노이즈를 100% 차단하기 위함입니다.
* **ADR-2: 묶음 호출 및 오디오 슬라이싱 사전 캐시 (Chunked Audio Pre-caching)**
  * 결정: 문장별 온디맨드 호출 대신, 씬/챕터 단위로 남녀 대사를 묶어 벌크 호출한 뒤 PCM 버퍼를 슬라이스하여 캐시 디렉토리에 미리 저장합니다.
  * 이유: 무료/티어 API 키의 Rate Limit을 극복하고, 사용자가 플레이어를 열었을 때 네트워크 딜레이(0ms) 없이 즉시 재생되도록 보장합니다.

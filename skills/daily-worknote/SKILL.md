# Daily Worknote (업무 일지 및 기술 작업 노트 표준 스킬)

본 스킬은 소프트웨어 개발 프로젝트에서 하루 동안 진행한 구현 내역, 기술적 의사결정, 버그 분석 및 해결 과정을 군더더기 없이 기록하고, 보안 위반 없이 영구 기술 자산으로 문서화하기 위한 표준 절차를 정의합니다.

---

## 1. 스킬 발동 조건 (Triggers)
사용자가 다음과 같은 의도를 표현할 때 즉각 활성화합니다:
* "오늘 작업 내용 정리해줘", "업무 일지 써줘", "작업 노트 기록해줘"
* "오늘 한 일 커밋용으로 정리해줘", "worknote 작성해줘", "/worknote"
* "기술 문서로 남겨서 나중에 다시 볼 수 있게 해줘", "ADR 작성해줘"

---

## 2. 5대 필수 보안 검증 원칙 (Security Zero-Leak)
업무 일지나 기술 문서를 작성하거나 원격 저장소에 커밋하기 전, 아래 항목을 **반드시 자체 스캔**하여 일절 유출되지 않도록 조치해야 합니다.

1. **비밀키 및 인증 토큰 절대 배제**:
   * Gemini, OpenAI, Claude, AWS, GCP, Slack 등 모든 API Key와 OAuth Token, JWT Secret, Session Token은 문서에 절대 평문으로 노출하지 않습니다.
   * 환경 변수 예시는 반드시 `process.env.GEMINI_API_KEY` 또는 `YOUR_API_KEY`와 같은 대체 템플릿으로만 서술합니다.
2. **비밀번호 및 계정 자격증명 차단**:
   * 데이터베이스 접속 주소, 비밀번호, 패스워드 해시, 마스터 관리자 비밀번호를 포함하지 않습니다.
3. **내부 사설 네트워크 정보 보호**:
   * 외부로 공개되지 않은 사내 VPN IP, 사설 인트라넷 호스트명, 내부 전용 포트 번호는 배제하고 개념적 표현(예: `사내 내부 게이트웨이`)으로 일반화합니다.
4. **개인 식별 정보(PII) 마스킹**:
   * 실명, 사원번호, 전화번호, 개인 이메일, 주민등록번호 등 개인정보보호법에 위배되는 데이터를 기록하지 않습니다.
5. **비공개 설정 파일 내용 직접 복사 금지**:
   * `.env`, `.env.local`, `credentials.json` 등 비공개 파일의 실제 내용을 문서 본문에 그대로 복사하지 않습니다.

---

## 3. 한국어 휴머나이징 및 작성 스타일 규칙 (Humanize Rule)
기계적인 AI 번역투를 배제하고 실무 엔지니어가 직접 쓴 듯한 자연스럽고 간결한 기술 문서체로 작성합니다.

* **Fidelity First**: 사실, 기술 수치, 함수/컴포넌트 이름, 파일 링크, API 엔드포인트는 왜곡 없이 100% 보존합니다.
* **격식체 유지**: 전문 기술 문서이므로 `하십시오체` 또는 `해라체`로 서술하며, 메신저식 구어체나 가벼운 어조로 흐르지 않습니다.
* **번역투 교정**:
  * ❌ `~에 대해(서)` $\rightarrow$ ⭕ 목적격 조사 직결 (`~를 논의하다`, `~를 검토하다`)
  * ❌ `~를 통해 / 통하여` $\rightarrow$ ⭕ `~로`, `~해서`, `~함으로써`
  * ❌ `~에 있어(서)` $\rightarrow$ ⭕ `~에서`
  * ❌ 이중 피동(`~되어진다`, `~되어지고 있다`) $\rightarrow$ ⭕ 능동 또는 단일 피동 (`~된다`, `~한다`)
  * ❌ 행위자 피동(`~에 의해 작성된`) $\rightarrow$ ⭕ 능동 (`~가 작성한`)
* **상투적 관용구 및 서두/결말 배제**:
  * `결론적으로`, `요약하자면`, `시사하는 바가 크다`, `매우 중요한 역할을 한다` 등의 공허한 미사여구를 일절 쓰지 않습니다.
  * `물론입니다!`, `요청하신 일지를 아래와 같이 정리해 드립니다.` 같은 챗봇 프레임 문장은 문서 파일 본문에서 완전히 제외합니다.

## 5. 단계별 실행 절차 (Workflow)

1. **상태 진단 및 변경점 수집**:
   * `git status`, `git diff --stat`, 최근 커밋 로그(`git log -n 5 --oneline`)를 조회하여 당일 수정된 파일과 로직을 정확히 파악합니다.
2. **보안 스캔**:
   * 작성할 내용 중에 API Key, 비밀번호, 토큰, 내부 IP가 섞여 있는지 검사합니다.
3. **일지 파일 및 아키텍처 문서 생성**:
   * `notes/YYYY-MM-DD-<slug>.md` 경로에 표준 템플릿으로 작성합니다.
   * 아키텍처 변경이 큰 경우 `docs/` 하위에 별도 상세 기술 문서를 분리합니다.
4. **인덱스 동기화**:
   * `index.md` 및 `README.md`에 새로운 일지와 문서를 추가하여 링크를 연결합니다.
5. **Git 커밋 및 푸시**:
   * `git add` 및 의미 있는 커밋 메시지로 커밋 후 지정된 원격 저장소에 푸시합니다.
